# healthadminbench: SOURCE
- Accessed 2026-11-10. Repo https://github.com/som-shahlab/health-admin-bench (main branch; Apache-2.0 LICENSE), site https://healthadminbench.stanford.edu (data/website_ready_results.json, 38 MB, in raw/), paper arXiv 2604.09937 (v1, 10 Apr 2026, CC BY 4.0). Tasks are public, not gated; all data synthetic.
- Population: 135 tasks (60 prior authorization, 60 appeals/denials, 15 DME; easy/medium/hard). Headline score = fraction of the 135 tasks with ALL subtasks passed. I sampled from `benchmark/v2/tasks` because the published runs (task ids, paper) were scored on v2; `benchmark/v3/tasks` has the same 135 ids with 132 identical goals (3 differ) and no published model results yet.
- Sample: random.Random(2026).sample(sorted 135 ids, 24) (9 prior auth, 10 appeals, 5 DME). Text = goal given to the agent + app name. Gold steps = len(metadata.step_by_step).
- Grading method: `state`. 1,698 subtasks: 1,177 deterministic JMESPath checks on final portal state, plus 521 LLM-judge rubrics (GPT-5.4 judge) for notes/appeals text. Mostly state-based with an LLM-judged minority; task passes only if every subtask passes.
- Description for time estimators: A revenue-cycle admin task in simulated hospital records, insurance-portal and fax web systems (e.g. check a referral, submit a prior-authorisation or appeal on a payer portal, attach documents, write a note); done when every required field, document and note is correctly recorded in each system.
- Human times: none published per item (paper only mentions hospital shadowing). Task JSON has step_by_step lists (gold step count).
- Scores: 5 models (7 agent rows in paper; 2 generic-harness duplicates dropped): main setting = screenshot-only, Task Description + Portal Guidance, one run each (best scaffold kept: native CUA for Claude Opus 4.6 and GPT-5.4). Reproduced from website per-run data to 3 decimals. Other settings (axtree, zero-shot, task_specific) are in raw/agg.csv and notes; task_specific prompts leak task hints (0.92+), not comparable.
- Problems: only 7 agents and effectively one date window (Mar-Apr 2026), 1 run per cell, so n small; README mentions newer models (gpt-6, claude-opus-5-5, ...) but no results are published in the files I found. Scores depend heavily on harness/observation mode (0.06 to 0.52 for one model). A process-check audit (raw/recomputed.md) shows small shifts. Release dates are from secondary sources; Kimi K2.5 and Qwen 3.5 dates unverified. Public environments only; the benchmark is fully public (not a subset).
