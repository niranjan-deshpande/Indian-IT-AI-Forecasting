# SWEeper-Bench (sweeper_bench)
- Items: https://huggingface.co/datasets/zlab-princeton/SWEeper-Bench (data/test.jsonl, sha f10cd684, lastModified 2026-10-16). Licence CC BY 4.0 (apps keep own licences). Not gated. Accessed 2026-11-09.
- Scores: https://sweeperbench.com/data/results.js (leaderboard table source); paper arXiv 2610.14096 (submitted 2026-10-08); repo github.com/zlab-princeton/sweeper-bench.
- Population: all 200 tasks (one per web app); headline = pass rate over all 200. Sample: random.Random(2026).sample(sorted(case_ids), 24). Item text = task_scoped prompt + repo; task_specified (bug description) and workflows deliberately excluded (hidden from agent).
- Grading method: `llm_judge` (agentic verifier). A browser-driving agent follows scripted target and preservation tests on the patched app; task passes if both pass. (Verifier is a model, though steps have explicit pass/fail criteria; reported >99% agreement with ideal.)
- Description for time estimators: Given an open-source web app's code and a running copy, plus a vague request such as "find and fix issues in <product area>" with no bug report, find the faulty behaviour by using the app in a browser and fix the code; done when the bug is gone and nearby features still work.
- Published human times: none. (task_specified allows a "bug already described" variant, ~96% pass, not a time measure.)
- Problems: single snapshot, 15 agents all from Jul-Sep 2026 release window, so little trend over time. Scores are per (model, harness) pair, one scaffold each; per-run eval dates not given (eval_date = paper date). Headline "pass" column used (target column differs by up to 1 pt for some rows). Several release dates missing or approximate (see notes); dates from third-party sites, not provider announcements. Full 200 tasks are public. Traces dataset zlab-princeton/SWEeper-Bench-traces exists (not downloaded).
